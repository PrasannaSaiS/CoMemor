Capabilities

Memory that engineers can actually trust.

Every capability is designed for credibility: append-only truth, statistical confidence, and defense-in-depth before anything touches disk or your agent's context.

Persistent memory

Append-only JSONL as the source of truth, with a SQLite FTS5 index rebuilt automatically. Durable, inspectable, diff-able — and designed to be committed to your repo.

Fuzzy lexical retrieval

Exact SHA-256 fingerprint matching for identical errors plus token-overlap similarity for structurally similar ones, with a configurable confidence threshold.

Secret redaction

API keys, tokens and credentials are stripped before anything reaches disk — deterministic regex patterns plus Shannon-entropy analysis across all stored fields.

Poisoning detection

7 heuristic detectors flag potential prompt-injection in stored records. Flagged records are quarantined and retrieved content is wrapped in untrusted-data envelopes.

Wilson-score confidence

Every remembered fix carries a statistical confidence interval for its success rate — plus staleness signals from lockfile hashes, normalizer versions and TTL decay.

Memory Console

A built-in local dashboard for audit and observability: browse records, quarantines, pending approvals and aggregate stats without leaving your machine.

How it works

Fail once. Fix once. Remember forever.

1

Agent hits an error

Before retrying anything, the agent calls find_fix. CoMemor searches by exact fingerprint or fuzzy lexical match and returns ranked candidates with confidence and staleness signals.

2

Fix is validated, not executed

verify_fix checks the proposed command against a safety policy — allowlisted binaries, no shell metacharacters, workspace containment — and returns a structured proposal. CoMemor never executes commands.

3

The repo gets smarter

Once a fix is confirmed working, record_failure persists it — secrets redacted — to repo-scoped memory. Next session, the same error resolves instantly instead of being re-investigated.

FAQ

Questions, answered straight.

Does CoMemor ever run commands on my machine?

No. verify_fix only validates a proposed command against a safety policy and returns a structured proposal with executedByServer: false. Execution always remains with your host IDE or agent, under its own confirmation mechanism.

Is the retrieval semantic / embedding-based?

No — and that's deliberate. Retrieval uses exact SHA-256 fingerprint matching for identical errors and fuzzy lexical token-overlap similarity for structurally similar ones. It's fast, deterministic, local and explainable.

Is it safe to commit the memory file to my repo?

The redacted records.jsonl is designed to be safe to commit. Redaction (regex + Shannon entropy) is best-effort — novel or custom secret formats may not be caught — so verify contents before committing to a shared repository.

Which IDEs and agents does it work with?

Any MCP 1.x host: Google Antigravity, Claude Desktop and Claude Code, Cursor, Windsurf, VS Code with Copilot, and more. The README includes ready-to-paste config snippets and agent setup prompts for each.

What do I need to run it?

Just Node.js ≥ 22.5.0 (CoMemor uses the built-in node:sqlite module). Run npx comemor — no install, no account, no cloud.

How is prompt-injection in stored memories handled?

Seven heuristic detectors scan records before retrieval; anything flagged is quarantined, and all retrieved content is wrapped in untrusted-data envelopes. It's best-effort defense-in-depth, documented honestly as such.
